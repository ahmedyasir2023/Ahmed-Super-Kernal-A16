# V10.3 HyperCore R2 — V9.2 RC3 rebased package audit

## Status
Offline package validation only. Not executed in physical OrangeFox; V10.3 has not been boot-tested on the RMX2170.

## Device evidence
OrangeFox reported the current Boot partition SHA-256:
`095ccb33240e763311637cb0b472b23745e662c2b3a82d49b87428f49914d725`.

This exactly matches the archived V9.2 RC3 / RC3 HF1 Boot image. The prior installer expected V9.1 RC1 (`c77d80ee...`) and correctly stopped before any write. R2 uses V9.2 RC3 as the exact accepted base and restore target.

## R2 metadata correction
R1 packages had a stale nested `boot_repack.base_v91_boot_sha256` field despite their V9.2 installer guards. R2 removes that stale V9.1 field and records V9.2 as the single authoritative base in all installer, restore and complete-package manifests. Kernel and Boot payloads are unchanged from R1.

## Additional guarded-flow simulation (host only)
The actual installer and restore scripts were executed under BusyBox ash against a temporary regular file used as a mocked Boot block. External partition hashes and persistent storage were stubbed solely for this isolated simulation:
- Install from exact V9.2 image: PASS; backup SHA verified; V10.3 write and readback SHA verified.
- Restore from exact V10.3 image: PASS; V9.2 write and readback SHA verified.
- Unknown/modified Boot: correctly refused at Guard 5, and the mocked Boot file remained byte-identical (no write).
This is a host-side control-flow simulation, not a physical block-device, OrangeFox, or handset test.
