# V7.7 RC2 — Normal Reboot / PMIC warm-reset diagnostic (NOT FLASHABLE)

Realme 7 Pro RMX2170 with Evolution X A16: device boots V7.7, fingerprint and KernelSU root work. But selecting **Restart** leads to a black/off state in which the ordinary power key does not start the phone; all-button entry into Fastboot permits booting System/OrangeFox. This issue may have existed on earlier kernels (user says 'still'), so no regression has been proven.

## Source-level evidence
- Linux's `kernel_restart` calls `arm_pm_restart`.
- Pinned Realme 4.14 `drivers/power/reset/msm-poweroff.c::msm_restart_prepare` chooses PMIC HARD_RESET unless a warm-reset exception applies.
- Device-tree `qcom,store-hard-reset-reason` is present in the relevant atoll/pm6150 DTBs, and `qcom,force-warm-reboot` is absent. For an ordinary reboot with empty reason and not in panic, this code selects PMIC HARD_RESET.
- Both types ultimately deassert PS_HOLD. Their actual physical behaviour depends on PMIC, bootloader, firmware and any variant-specific hardware properties. The reason the PMIC does not automatically reboot is not yet proven.
- The V7.2–V7.7 kernel patches do not change `msm-poweroff.c`; identifying the path does not prove the issue was introduced by V7.7.

## Proposed controlled source change
Adds a boolean module parameter `ay_normal_warm_reset_probe` to the existing kernel driver:
- Default **OFF** after each boot: vendor reboot path unchanged.
- Mode 0600: only root can enable it, and only for a deliberate future diagnostic.
- When enabled, ordinary reboot with no reason and no panic uses PON_POWER_OFF_WARM_RESET.
- Does NOT override explicit bootloader/recovery/EDL/other named reasons, panic, actual shutdown or the power-button key driver.
- No timers, polling, background service, changes to energy settings, DT2W, fingerprint, Kernelsu/SUSFS, temperature or DeepDoze.

## Evidence that must be collected BEFORE another reboot test
Current boot / previous shutdown:
- `/sys/fs/pstore/*ramoops*` (where available), selected `dmesg`, `logcat` powerctl messages.
- `ro.boot.bootreason`, `sys.boot.reason` and `uname -r`.
- Confirm whether Android requested a normal reboot or an actual shutdown (AOSP init distinguishes these).

Collect through read-only script `scripts/v7/AY_RMX2170_Reboot_Diagnostics.sh` and review before sharing; persistent logs may contain private metadata.

## Safety gate
Do not flash diagnostic kernel or toggle any PMIC settings now. Even a successful build cannot prove Warm Reset safe or rule out a ROM/vendor firmware mismatch. A supervised on-device test must have independently recoverable Boot, sufficient battery, access to OrangeFox/Fastboot, and an explicit user decision. Never attempt EDL, flash firmware or disable watchdog as a workaround.
