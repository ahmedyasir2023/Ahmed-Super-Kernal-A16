# Ahmed Super Kernal A16 V7.6 — Reclaim Observability

Development-only nonflashable build, directly based on successful V7.5 Reclaim Progress CI.

## Purpose

A code fix that compiles does not establish that it cures the user's high memory PSI or kswapd CPU usage. V7.6 adds a read-only procfs observation point so a future A/B device test can distinguish excessive reclaim requests, unbalanced pressure with no waiting allocator, and inability to reclaim pages. No code change to the reclaim algorithm or thresholds is made in V7.6.

## New optional runtime interface

Path: /proc/ay_reclaim_status (0444, available when CONFIG_PROC_FS is enabled).

Fields:
- balance_calls: number of calls to balance_pgdat().
- balance_zero_waiters: calls entered when the globally tracked allocator-waiter count is zero. A zero count is not equivalent to sufficient free memory.
- balanced_exits: cycles that exited after verifying a balanced zone.
- zero_progress_cycles: cycles where balance_pgdat finished with no reclaimed pages and incremented its normal failure counter.
- wakeup_requests: event count at wakeup_kswapd() after the original active-queue, balance and failure checks.

All five are monotonic event counters, not rates. Compare deltas of two readings against PSI and vmstat. With two kswapd workers, sums include both. Results do not by themselves identify an app, a battery drain amount or an LMKD kill. Read-only access works when procfs is mounted normally and kernel security permits it.

The existing /proc/vmstat, /proc/buddyinfo, /proc/zoneinfo, /proc/pressure/memory and /sys/block/zram0/{mm_stat,use_dedup,dedup_stat} remain authoritative complementary data sources.

## Power contract

No new periodic work, timers, kthreads, wakelocks, performance frequency pins, or services. The added atomic counter increments occur only on existing reclaim and wakeup execution paths, so they can introduce a small amount of execution overhead during actual memory pressure; it has not yet been measured. The original V7.2 CPUBoost, DT2W, 600s deferrable DeepDoze and InstantWake source checksums are verified again by CI.

## Root cause and remediation status

V7.5 removed a vendor-specific zero-waiter early exit in balance_pgdat, restoring upstream Linux v4.14 watermark-driven flow. Whether that improves or worsens the observed stall is not established.

The current ROM's vendor init requests a background memcg swappiness value of 140, which the pinned memcg interface rejects; this alone is not proven to cause the user's kswapd problem. Similarly, configured ZRAM dedup support does not mean use_dedup is enabled.

Do not automatically change kswapd_threads, direct_swappiness, ZRAM algorithm, LMKD or cgroup policy without measured device evidence; a previous one-thread test did not resolve the high PSI.

## CI and release policy

V7.6 CI reproduces V7.2-V7.5 source patch chain, injects telemetry with exact-match guards, runs source assertions and the complete ARM64 build, checks KernelSU Next/SUSFS objects and original device-tree binary hashes. The artifact is NONFLASHABLE. No installation is required or requested.

The user stays on working V7.2. Before any eventual OrangeFox release: compare active PSI, swap churn, reclaimed/scanned deltas, screen-off battery drain, suspend, fingerprint, DT2W and wake speed against V7.2 in controlled on-device trials.
