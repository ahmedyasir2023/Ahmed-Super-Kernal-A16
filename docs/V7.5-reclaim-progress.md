# Ahmed Super Kernal A16 V7.5 — Reclaim Progress (development; no flash)

## Scope and provenance
Base: V7.4 ZRAM Dedup Integrity (successful ARM64 CI run 41876416199).
Target: Realme 7 Pro RMX2170, Evolution X A16, user-installed kernel V7.2.
The user explicitly requested continued development but **no newer kernel installation** yet.

## Confirmed source mismatch
The pinned Realme Atoll Linux 4.14 `mm/vmscan.c` adds a condition
`|| !atomic_long_read(&kswapd_waiters)` to the break from `balance_pgdat()`.
Upstream Linux v4.14 stops here only for freezer or kthread shutdown.

When the last allocator waiter is no longer waiting but a zone remains
below high watermark, the Realme branch can exit balance_pgdat early;
kswapd_try_to_sleep() may then reject sleep due to low watermarks, so the
next iteration may enter and exit reclaim again. This is a *plausible*
busy-loop mechanism and should not be mistaken for a confirmed diagnosis
of the user's reported kswapd 100% or PSI full 60%-70%.

## V7.5 patch
Remove **only** the waiter-count early-exit condition from balance_pgdat.
Leave zone watermarks, priority escalation, failure accounting, kswapd
sleep, freezer/stop, direct-reclaim throttling, and all waiter bookkeeping
untouched. Aligns this exit with Linux v4.14 upstream. No new timer,
background daemon, governor, sysctl, global/cgroup swappiness, LMKD or
ZRAM configuration.

**Tradeoff:** If a zone is genuinely under pressure, kswapd may do *more*
reclaim work instead of dropping the pass, which may increase energy
consumption during that pressure. Power benefit is not established.
