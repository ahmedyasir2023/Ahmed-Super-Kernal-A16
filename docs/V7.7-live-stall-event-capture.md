# V7.7 — live PSI/kswapd stall capture (no flashing)

## Current verified evidence
Realme 7 Pro RMX2170 / Evolution X Android 16 / Ahmed Super Kernal A16 V7.7:
- Original thermal-bypass module disabled: both vendor thermal services operate normally.
- With all external KernelSU modules off, memory full PSI still reached about 78% with two `kswapd` threads close to a full CPU core each.
- Initial A→B test changing `reclaim_progress` from 0 to 1 showed a large improvement; the independent A→B→A experiment did **not** reproduce a reversible effect. There is no basis for enabling mode 1 by default.

## Purpose
`AY_V77_Live_Stall_Recorder.sh` waits for a **real** stall rather than sampling an already-idle phone. It checks cumulative PSI totals and worker CPU tick deltas while also retaining zone watermarks.

## Behavior
- One foreground run. Maximum trigger-wait approximately **60 seconds**, with memory PSI `full avg10 >= 25%` on two consecutive checks spaced three seconds apart.
- If triggered, takes four snapshots about five seconds apart.
- Captures `/proc/pressure/{memory,cpu,io}`, VM scan/steal, swap/refault and allocation-stall counters, memory availability, `/proc/zoneinfo` selected fields, compressed ZRAM sizes, V7.7 reclaim counters and per-worker kswapd CPU ticks.
- Rejects a non-root call, missing Thermal HAL, non-default reclaim mode, and missing PSI. It **never writes** to the kernel, PMIC, swap, sysfs, Android properties, governor, or root modules.
- Creates only the diagnostic TXT in Download. Output may show process and kernel data: review before sharing.
- If the event does not occur during the observation window, reports `NO_TRIGGER`; no conclusion on whether the problem is fixed can be drawn.
- Stalling may itself disrupt or terminate the user-space collector; an interrupted or incomplete file is **not valid evidence of a finished event**.

## Device usage
Download `scripts/v7/AY_V77_Live_Stall_Recorder.sh` to the phone's Download folder and run once in Termux while the screen stays ON:

```sh
su -c 'sh /sdcard/Download/AY_V77_Live_Stall_Recorder.sh'
```

Share `/sdcard/Download/AY_V77_Live_Stall_Report.txt`.

The Python analyzer `scripts/v7/AY_V77_Live_Stall_Analyzer.py` is for desktop use after the report is captured; it validates four samples, stable PIDs, unmodified reclaim mode, monotonic counters and interval PSI stall fractions.

## Limitations and decision
Without real zone-watermark and contention events it remains impossible to prove that the vendor multi-kswapd implementation is at fault. Zone `free` being above or below `high` alone is not decisive due to order/reserves and classzone selection. CPU tick rates are not CPU percentages without knowing USER_HZ.

Do **not** install or merge any default-on reclaim patch or use Thermal Bypass. Working V7.7 DT2W, fingerprint, root, normal reboot and DeepDoze are the safety baseline.
