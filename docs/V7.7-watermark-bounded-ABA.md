# V7.7: observed high memory PSI and large Normal-zone watermarks

## Verified owner data (2026-11-05)

Captured by `AY_V77_Live_Stall_Recorder.sh` while V7.7 had `reclaim_progress_enabled=0`. Consecutive 5+6+5 second periods:

| Observation | Result |
| --- | ---: |
| Cumulative memory PSI full | **76.45% of 16s** |
| Cumulative memory PSI some | **81.02% of 16s** |
| Total kswapd0:0 + kswapd0:1 CPU ticks | **3,226** |
| kswapd scanned pages | 17,133 |
| kswapd stolen pages | 3,275 (19.12% of scanned) |
| `balance_pgdat()` entry counter increase | 973 |
| `balanced_exits` increase | 0 |
| `pgscan_direct` change | 0 |
| `pswpout` change | 0 |
| MemAvailable end | 559,504 KiB |

At the final snapshot (`/proc/zoneinfo`), Normal-zone **free=24,332**, **low=32,130**, **high=54,898** pages. Movable-zone free=374, min=398, low=7,397, high=12,639 pages. These are hardware readings, not synthetic values.

The owner previously reported `/proc/sys/vm/watermark_scale_factor=200`. The pinned Realme Linux 4.14 kernel uses default **10** in `mm/page_alloc.c`; its `__setup_per_zone_wmarks()` derives high/low with `extra_free_kbytes` and `watermark_scale_factor / 10000`. Importantly, **200 is a configuration, not proof of a bug**.

For the captured Normal zone, observed high-low gap is **22,768 pages** (roughly 2% of managed pages). Holding managed pages, min and extra_free_kbytes constant, setting scale factor to **50** would predict a high watermark near **20,746 pages** (versus observed free 24,332). This *could* help kswapd sleep, but zone class eligibility, allocation reserves, watermarks of other zones, and workload are relevant. It could also increase direct reclaim or allocation latency. This is an **unverified hypothesis**.

## Bounded reversible test — not a kernel release

`scripts/v7/AY_V77_Watermark_ABA_Trial.sh` only tries one kernel sysctl:
- Requires observed original `watermark_scale_factor=200`, `reclaim_progress=0`, root, normal running thermal services and battery temperature <=42°C.
- Waits up to roughly 60 seconds for **two consecutive memory full avg10 >=25%** observations.
- Performs original-mode A1 for 15 seconds, **requires an independently measured A1 full PSI >=25%**, then changes factor **200 to 50** for a 15-second B segment.
- Restores factor **200** for a 15-second A2 segment. An exit/signal trap retries restoring the original and records a readback confirmation. **SIGKILL and device power loss cannot trigger shell traps.**
- Reads `/proc/zoneinfo`, PSI cumulative totals, kswapd CPU ticks, direct reclaim, OOM, swap activity and `MemAvailable` at six boundaries.
- Changes **no** kswapd worker counts, swappiness, LMKD properties, governors, thermal HAL, boot files, KernelSU Next modules or recovery contents. No persistent service is installed.
- If A1 is already quiet, exits without writing to the sysctl.

Run explicitly with screen on after placing the script into Download:

```sh
su -c 'sh /sdcard/Download/AY_V77_Watermark_ABA_Trial.sh'
```

The output is `/sdcard/Download/AY_V77_Watermark_ABA_Report.txt`, with a final `RESTORED watermark_scale_factor=200` line if the parameter was changed and properly restored. **Always check this line**. If restoration is not confirmed, check `cat /proc/sys/vm/watermark_scale_factor`; if it remains at 50 and root is working, restore the original 200 before further tests.

The offline `AY_V77_Watermark_ABA_Analyzer.py` rejects incomplete or inconsistent data and inspects both PSI and the risk of rising `pgscan_direct`, `allocstall_*` or `oom_kill`.

**Release gate**: A brief A-B-A improvement only justifies further investigation, not a default value of 50, a flashable ZIP, or a claim of battery benefit. Keep installed V7.7 and existing DT2W, fingerprint, root, DeepDoze and Thermal HAL intact.
