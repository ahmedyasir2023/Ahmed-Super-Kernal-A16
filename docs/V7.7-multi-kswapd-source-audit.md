# V7.7 source-audit priorities after the live watermark A-B-A

## What is established

- On RMX2170 with all third-party KernelSU modules disabled and Thermal HAL running, memory full PSI has repeatedly exceeded 70%, and both `kswapd0:0` and `kswapd0:1` have consumed close to one CPU core each.
- A finite 200→50→200 `watermark_scale_factor` reversal experiment under actual stalls produced full-PSI **70.69→45.46→76.51%** and combined kswapd CPU ticks **3422→2160→3433**, in 17-second arms.
- **Candidate=50 is not a complete fix.** It had **1262 direct-reclaim scans and 8 new Normal-zone allocstalls** in 17 seconds; it also coincided with higher swap-ins (3945 vs 2211) and major faults (4434 vs 2881) than A1.
- In B's final snapshot, Normal free 24848 pages exceeds high 20746; Movable free 13379 exceeds high 4775. Nevertheless kswapd consumed about 2160 CPU ticks during the B arm. This is evidence to study the sleep path, but a raw free-vs-high comparison cannot adjudicate allocator order, reserves or classzone restrictions.
- `MemAvailable` is an estimate that depends partly on zone watermarks; a large instantaneous increase after lowering the scale factor **does not imply equivalent physical memory was freed**.

## Source paths to audit (no behavioral patch authorized yet)

1. `mm/multi_kswapd/multi_kswapd.c`: `kswapd_run_ext()` creates one `kswapd()` kernel thread for each `kswapd_threads` entry. Vendor source initializes this variable to 1; the observed device sysctl shows 2. The source alone does not identify which ROM/service configured the runtime value.
2. `mm/vmscan.c`: both threads use the **same pgdat instance**, `pgdat->kswapd_wait`, `pgdat->kswapd_order`, and `pgdat->kswapd_classzone_idx`. In `kswapd()` each worker clears the shared order/classzone fields after waking. This is an area to inspect for concurrent wakeup/order handling, **not evidence that a race has been proved**.
3. `mm/vmscan.c` `pgdat_balanced()` / `prepare_kswapd_sleep()`: balancing uses `zone_watermark_ok_safe(zone, order, mark, classzone_idx)`; a simplistic comparison of zone free vs high omits allocation reserves/order. Inspect when balancing fails for each worker and classzone, and whether work is duplicated.
4. `mm/vmscan.c` `balance_pgdat()`: the vendor's early-exit on `!atomic_long_read(&kswapd_waiters)` differs from an ordinary global count of allocators; `kswapd_waiters` in this source tracks specially throttled direct reclaimers only. Avoid describing the count as all memory demand.
5. `mm/page_alloc.c` `__setup_per_zone_wmarks()`: `watermark_scale_factor` and `extra_free_kbytes` together influence LOW/HIGH watermarks; the installed factor 200 is far above the source default 10.

## Design guardrails for a future source-only candidate

- Retain stable V7.7 boot, kernel root, DT2W, fingerprint and 600s DeepDoze; never resurrect unmerged PMIC reboot experiments.
- Do not change `kswapd_threads` dynamically without assessing the vendor `kthread_stop` hotplug path and robust rollback. No default-to-one assumption yet.
- Do not default `watermark_scale_factor` to 50 until direct-reclaim, allocstall, major-fault, app-launch latency and battery regressions are evaluated in repeatable normal use.
- Prefer adding low-overhead **diagnostic counters only** in a source-only branch (e.g. `pgdat_balanced()` failure by worker/order/classzone, kswapd wake/sleep transitions) before changing policies. Such instrumentation requires a separate kernel build and must not be automatically flashed.
- No blanket thermal bypass, no blanket scheduler performance locks, no ZRAM reset or LMKD disable.
