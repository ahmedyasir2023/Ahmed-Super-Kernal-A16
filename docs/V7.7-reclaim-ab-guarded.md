# V7.7 Reclaim A/B Guard — development, NOT FLASHABLE

Base: V7.6 Reclaim Observability (ARM64 CI run 41889544531 succeeded). Previous V7.3–V7.6 fixes and counters retained.

## Reason for this stage

V7.5 made upstream Linux 4.14 watermark-driven kswapd reclaim unconditional by removing the vendor's waiter-zero early exit. The change may improve a tight CPU loop but may also perform *more* reclaim and use energy while memory is stressed. Passing CI does not show a battery win. The user's V7.2 exhibited unchanged displayed battery percent over 30 minutes screen-off, and the new release must not silently jeopardize idle behavior.

## Safe-by-default A/B

- A new built-in root-only boolean parameter `ay_reclaim_progress`, mode 0600, defaults false every boot.
- `0`: V7.2 original vendor reclaim early exit based on `kswapd_waiters`. This is the default; not a claim that the entire kernel is identical to V7.2, because V7.3/4 safety fixes and V7.6 counters remain present.
- `1`: V7.5 upstream-aligned watermark-driven reclaim, for a deliberate A/B test.
- The selected mode is displayed in read-only `/proc/ay_reclaim_status` as `reclaim_progress_enabled=0/1`.
- No automated mode switching, timers, services, wakelocks or persistent boot properties. The setting resets to 0 on reboot.
- Expected sysfs path if exported by this built-in module parameter: `/sys/module/vmscan/parameters/ay_reclaim_progress`. Presence/permissions are to be confirmed on hardware.

## Future explicit supervised test only (DO NOT RUN NOW)

A future tester can inspect with root:
```sh
su -c 'cat /sys/module/vmscan/parameters/ay_reclaim_progress'
su -c 'cat /proc/ay_reclaim_status'
```
Opt-in during a controlled **screen-on** workload only:
```sh
su -c 'echo 1 > /sys/module/vmscan/parameters/ay_reclaim_progress'
```
Before putting the phone to sleep, rollback without reboot:
```sh
su -c 'echo 0 > /sys/module/vmscan/parameters/ay_reclaim_progress'
```
Reboot also resets to 0. Do NOT install V7.7 now: the artifact is nonflashable, no hardware testing has occurred, and no rollback installer has been prepared.

## Acceptance / A-B metrics

For comparable short screen-on sessions, compare deltas of `/proc/ay_reclaim_status`, `pgscan_kswapd`, `pgsteal_kswapd`, `pswpin`, `pswpout`, PSI memory `some/full` and per-worker CPU time; compare 0/1 only on the SAME kernel after a stabilization interval, and never infer energy from one rounded battery percentage. Stop if temperature, freezes or stalls increase. Outside screen-on tests keep mode 0. A/B software test does not by itself prove the root cause.

DeepDoze 600s, touch/DT2W, InstantWake, fingerprint, KernelSU Next, SUSFS, original DTBs, SELinux, thermal and ZRAM settings unchanged.
