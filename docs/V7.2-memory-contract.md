# V7.2 memory statistics and HyperSpeed contract

Base: V7.1.1 `456537cda0c56d6187fd0aa56ddb22f3d588f0d3`, pinned Realme Atoll Linux 4.14.336.

## Device observations (4 Nov 2026)
After boot: `memory PSI full avg10=15.84%`, `some=17.43%`, ~605 MB MemAvailable, ~1.46 GB swap used; `kswapd0:1` sampled at 6% CPU (much lower than ~200% combined before reboot). High PSI after reboot remains unresolved; **no measured battery fix claimed**.

Vendor `drivers/block/zram/zram_drv.c:mm_stat_show` passes seven arguments but its `scnprintf` format has ten conversions. Three trailing fields contain uninitialized values. Fix format to seven conversions only, preserving the first seven documented counters and all ZRAM allocator, deduplication, LMKD, kswapd, compressed-memory and RAM-management behavior.

On a previous device sample the second counter `compr_data_size` appeared as a huge value, but after reboot it was 247168255 bytes. The new formatter does not establish or fix the underlying cause of any actual accounting underflow. The recurrence of this number must be independently monitored.

Runtime showed `input_boost_ms=80` and `sched_boost_on_input=2`, in conflict with requested V7.1.1 build defaults. Make five numeric boost parameters `0444`, preserving **touch 72%/105ms**, **wake 82%/155ms**, and **scheduler 3** across writes via sysfs. `ay_auto_input_boost`, screen-off state and thermal restrictions are untouched. **This blocks third-party runtime tuning of those five numbers** and must be verified against the ROM; if ROM Power HAL needs writable parameters, revert this experimental lock.

DeepDoze continues **600 seconds after screen blank**, one-shot deferrable; DT2W, KernelSU Next, SUSFS footprint, vendor DTBs, SELinux and thermal control are unchanged.
