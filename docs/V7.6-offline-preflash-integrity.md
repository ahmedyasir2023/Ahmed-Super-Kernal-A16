# V7.6 — Offline preflash integrity audit (NO FLASH)

This is a **release-engineering check only**. It changes no kernel source, never flashes a partition, never writes a boot image, and does not establish device bootability.

## Evidence / inputs (provided by device owner)

- Original working V7.2 experimental OrangeFox ZIP: `Ahmed-Super-Kernal-A16-V7.2-OrangeFox-GUARDED-EXPERIMENTAL.zip`
- V7.2 CI artifact: `A16-V7.2-MEMORY-STAT-HYPERSPEED-NONFLASHABLE.zip`
- V7.6 successful CI artifact: `A16-V7.6-RECLAIM-OBSERVABILITY-NONFLASHABLE.zip`, GitHub Actions run [41889544531](https://github.com/ahmedyasir2023/Ahmed-Super-Kernal-A16/actions/runs/41889544531), artifact 13355135518.
- Device/ROM: RMX2170 / Evolution X Android 16 (2 Nov 2026). Actual device flash or reboot **not performed**.

The pinned V7.2 reference Boot is 64 MiB, version 2 and contains an unsigned AVB hash descriptor. The simulator fails closed for an unknown Boot or signed AVB instead of forging a signature.

## Checks performed locally with the actual files

- V7.2 Boot SHA-256 matches the known-good recovery image: `afdc040fc98dc03009d1fdab81cba4d8c23f3d1d42e2a0e4a151ee787e326f3a`.
- The V7.2 Boot's embedded compressed kernel matches its CI output.
- V7.6 kernel SHA-256: `6af64382f1370bad6198f8b941f9173f296ad47553d6a099866de7b2354a591b`; old/new lengths 19,645,357 / 19,647,326 bytes. Both fit into the exact same reserved 19,648,512-byte kernel span, so the ramdisk/DTB offsets remain unchanged.
- RAMDISK SHA-256 unchanged: `9907076b0a45ce9afc1fb950d42f860e29e25f02cea3172e3dda288c406bf923`.
- DTB SHA-256 unchanged: `212d8e40f9d3025c92f1c11c2dc40761820dc5310c41bafbc48a88bd39d23af8`.
- Simulated Android legacy Boot SHA-1 recalculated and verified.
- Simulated embedded unsigned AVB SHA-256 hash descriptor recalculated and verified (original salt retained); AVB footer untouched.
- Exact dry-run result, hypothetical Boot SHA-256 **without writing any Boot image**: `bb6aeb995b890b094327542d51ffd076dfcbe5568da410838dce183d3b0f6ad6`.
- Full same-kernel V7.2 self-reproduction returned the byte-identical original Boot SHA-256. Deliberate tampering of the reference kernel, RAMDISK, DTB and AVB hash was rejected.

## Reproduce offline (outside CI)

```bash
python3 scripts/release/ay_v76_preflash_dryrun.py \
  --known-boot-zip 'Ahmed-Super-Kernal-A16-V7.2-OrangeFox-GUARDED-EXPERIMENTAL.zip' \
  --v72-ci-zip 'A16-V7.2-MEMORY-STAT-HYPERSPEED-NONFLASHABLE.zip' \
  --new-ci-zip 'A16-V7.6-RECLAIM-OBSERVABILITY-NONFLASHABLE.zip' \
  --report v76_preflash_dryrun.json
```

The user boot archives are deliberately NOT committed to this repository. GitHub CI uses synthetic fixture tests only, including rejection of signed/malformed AVB, malformed boot header and corrupt hash descriptor.

## What this DOES NOT prove

- Real device Boot or working KernelSU Next, fingerprint, DT2W, Wi-Fi, calls or suspend.
- Compatibility with external `vbmeta` / verified boot policy.
- That the user's **currently installed** V7.2 partition is byte-for-byte identical to the older installer payload.
- Any improvement to memory PSI, kswapd CPU, application responsiveness or battery draw.

**Do not install V7.6. Keep the known-good V7.2 image and separate OrangeFox backup until an explicit future test decision.** This PR is for offline integrity only.

Source documentation: [Android boot image header](https://source.android.com/docs/core/architecture/bootloader/boot-image-header), [Android Verified Boot](https://android.googlesource.com/platform/external/avb/+/master/README.md).
